# CASEFLOW v0.8 — Network Intelligence & Fast Intake

This phase adds the second operator-convenience wave while preserving the v0.7 permission, tenant, attribution, View As, search, exception, and assistant foundations.

## Added capability foundations

1. Publisher Health Score — snapshot model with contactability, consent, qualification, duplicate-control, and firm-acceptance components.
2. Publisher Caps — daily/weekly/monthly campaign/state/case-type limits with hard-stop policy.
3. Agent Performance — lead, contact, qualification, response-time, and rate snapshots.
4. View As Search — tenant-tree constrained user/role discovery for support.
5. View Organization As — supported by organization tree + role-based View As; UI demo provides organization-role entry.
6. Permission Explanation — returns effective permissions and explains parent/platform ceiling behavior.
7. Dynamic Intake — browser demo conditionally reveals rideshare, commercial, and motorcycle questions.
8. Autosave — production draft API stores draft payload encrypted with the application PII key and expires drafts after seven days.
9. Keyboard-First Intake — browser demo shortcuts reduce mouse dependence; production UI should preserve accessible alternatives.
10. Inline Editing — whitelisted fields only, write permission required, with redacted before/after audit evidence.

## Security notes

- Publisher intelligence is scoped to an authorized network ancestor.
- Publisher cap changes require descendant administration rights and are audited.
- View As search does not broaden data visibility; it only discovers accounts inside the caller's authorized network tree.
- Drafts can contain claimant PII and therefore are encrypted before database storage.
- Inline editing uses a strict field allowlist and writes a separate immutable edit event plus the platform audit event.
- Production UI must continue enforcing View As read-only sessions server-side on every mutation route.
