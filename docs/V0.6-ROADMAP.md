# CASEFLOW v0.6 Roadmap — Staging, Approval SLA & Billing Workflow

## Objective

Convert the v0.5 foundation and browser walkthrough into a database-backed staging environment that can demonstrate the full flow without real claimant data while laying down production-grade workflow primitives.

## Super Admin SLA settings

- Platform default law-firm review period, stored in elapsed hours.
- Configurable by Platform/Super Admin only.
- Recommended validation range: 1–720 hours unless contract policy defines tighter bounds.
- Optional law-firm-specific override.
- Every change creates an immutable audit event with actor, old value, new value, timestamp, and reason when required.
- At confirmed successful delivery, snapshot the effective SLA onto the delivery/matter record.
- Later global or firm-setting changes must never rewrite a running matter's deadline.

## Law-firm approval workflow

`PACKET_READY -> DELIVERY_PENDING -> DELIVERED_REVIEW_OPEN -> ACCEPTED | REJECTED | CORRECTION_REQUESTED | AUTO_BILLABLE`

Rules:

- Review clock starts only after successful delivery is confirmed.
- Bounce/failure does not start the SLA.
- Acceptance can immediately mark the matter billable under the configured commercial agreement.
- Rejection must use a contract-valid reason code and be timestamped before the deadline.
- Ordinary rejection should lock after the SLA expires; later challenges use a dispute workflow.
- Correction requests do not silently change financial status; contract policy must define whether/how they pause the SLA.

## Financial disposition

Keep firm disposition and billing disposition separate.

Firm disposition examples:
- `PENDING`
- `ACCEPTED`
- `REJECTED`
- `CORRECTION_REQUESTED`
- `AUTO_BILLABLE`

Billing disposition examples:
- `PENDING`
- `BILLABLE_ACCEPTED`
- `BILLABLE_SLA_EXPIRED`
- `NON_BILLABLE_VALID_REJECTION`
- `DISPUTED`

Financial transitions should be append-only/audited rather than mutable status edits without history.

## Firm delivery and portal

- Secure notification email with authenticated portal link; avoid ordinary sensitive attachments.
- Delivery-provider event/idempotency handling.
- Firm portal shows claimant/matter information according to least privilege.
- Accept, reject, request correction, view/download released packet, and review consent/source evidence.
- Reminder events configurable from Super Admin (for example 24h, 12h, 1h remaining).

## Messaging

- Preserve `MOCK_GATEWAY` for demos and tests.
- Add production SMS adapter only after provider selection and compliance/vendor approval.
- Generic secure-link SMS; no sensitive details in ordinary message content.
- Central STOP suppression is provider-independent.
- Production webhooks require signature verification and idempotency.

## Staging target

Deploy a password-protected test environment using only fake data. The marketing-firm presentation should support:

Marketing Lead -> Central Intake -> Qualification -> Mock SMS -> Claimant Upload -> Document QC -> Firm Routing -> Secure Firm Delivery -> SLA Review -> Billing -> Retainer -> Audit

## Still not production-ready until

- Real infrastructure/runtime validation.
- Managed database/object storage/KMS/secrets.
- Production vendor integrations and agreements.
- Security assessment and compliance/risk review.
- Access review, retention/legal hold, SIEM, WAF, backup/restore, incident response, and production operational controls.
